## Project Overview

Quartz v4 is a static site generator for publishing digital gardens and notes as websites. It transforms Markdown files into a fully-functional website with features like backlinks, graph views, search, and wiki-style popovers.

## Development Commands

### Build and Serve
- `npx quartz build` - Build the site once
- `npx quartz build --serve` - Build and serve locally with live reload
- `npx quartz build --serve -d docs` - Build and serve from docs directory

### Code Quality
- `pnpm check` - Run TypeScript type checking and Prettier format check
- `pnpm format` - Auto-format code with Prettier
- `pnpm test` - Run tests using tsx test runner

### CLI
- `pnpm quartz` - Main CLI entrypoint (wraps `./quartz/bootstrap-cli.mjs`)

## Architecture

### Core Build Pipeline

The build process follows a three-stage pipeline defined in `quartz/build.ts`:

1. **Parse** (`quartz/processors/parse.ts`) - Transforms Markdown files into AST using unified/remark
2. **Filter** (`quartz/processors/filter.ts`) - Applies filter plugins to determine what content to publish
3. **Emit** (`quartz/processors/emit.ts`) - Generates output files (HTML, assets, etc.)

### Plugin System

Quartz uses three types of plugins configured in `quartz.config.ts`:

- **Transformers** - Process Markdown/HTML during parsing (syntax highlighting, link processing, LaTeX, etc.)
- **Filters** - Determine which content should be published (e.g., RemoveDrafts)
- **Emitters** - Generate output files (pages, assets, RSS, sitemap, etc.)

Each plugin type has a specific interface defined in `quartz/plugins/types.ts`.

### Configuration Files

- `quartz.config.ts` - Main config (plugins, theme, analytics, locale, ignore patterns)
- `quartz.layout.ts` - Page layouts and component placement (header, footer, sidebars)
- Both files are TypeScript and directly imported by the build system

### Component System

Components live in `quartz/components/` and use Preact (not React). Each component:
- Exports a function that returns a `QuartzComponent`
- Can have both SSR and client-side scripts (*.inline.ts files)
- Is configured in `quartz.layout.ts` for placement on pages

Layout structure:
- `sharedPageComponents` - Header, footer, afterBody (across all pages)
- `defaultContentPageLayout` - Single note pages (beforeBody, left sidebar, right sidebar)
- `defaultListPageLayout` - Tag/folder listing pages

### File Organization

- `quartz/components/` - UI components (Preact/TSX)
- `quartz/plugins/` - Plugin system (transformers, filters, emitters)
- `quartz/processors/` - Build pipeline stages
- `quartz/util/` - Shared utilities (path handling, theme, logging, etc.)
- `quartz/styles/` - Global SCSS styles
- `quartz/static/` - Static assets copied to output
- `quartz/i18n/` - Internationalization locale definitions

### Key Concepts

- **Slugs** - URL-safe file paths generated by `slugifyFilePath()`
- **ProcessedContent** - Parsed Markdown file with metadata, stored as vfile
- **BuildCtx** - Context object passed through build pipeline containing config, file lists, etc.
- **Incremental builds** - Watch mode tracks changes and rebuilds only affected files

## Technical Notes

- Uses ES modules (`"type": "module"`)
- Preact for components with `jsxImportSource: "preact"`
- Requires Node >=22
- Use `pnpm` for package management
- Strict TypeScript enabled
- Tests run via tsx test runner

## Common Patterns

- Creating new components: Follow structure in `quartz/components/`, export QuartzComponent
- Adding transformers: Implement QuartzTransformerPlugin interface, add to config
- Customizing theme: Edit colors/typography in `quartz.config.ts` theme object
- Modifying layouts: Edit `quartz.layout.ts` to rearrange components
